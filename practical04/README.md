# Практична робота 04: Проєктування рішення навколо фіксованого класифікатора

## 1. Тема та мета роботи

**Тема:** Побудова системи прийняття рішень на основі фіксованого бінарного класифікатора для набору даних Hill-Valley.

**Мета:** Зафіксувати модель, preprocessing та експериментальний протокол; отримати OOF-бали для подальшого аналізу порогів і наслідків помилок.

---

## 2. Постановка задачі

### 2.1. Контекст рішення

**Що означають класи?**

- `y = 0` — **Valley** (долина). На графіку 100 точок утворюють «западину».
- `y = 1` — **Hill** (пагорб). На графіку 100 точок утворюють «горб».

**Яку дію запускає прогноз `ŷ = 1`?**

У прикладній системі (наприклад, модуль аналізу рельєфу для автономного дрона або геоінформаційної системи) прогноз `ŷ = 1` означає, що **виявлено пагорб**. Це запускає дію: **система позначає ділянку як потенційну височину** та передає її на подальший аналіз (наприклад, для побудови 3D-моделі або коригування маршруту).

**Що відбувається за прогнозу `ŷ = 0`?**

Прогноз `ŷ = 0` означає, що **виявлено долину**. Система позначає ділянку як **низовину** і може використовувати її для прокладання безпечного маршруту або виключення з зон підвищеного ризику.

**Хто виконує дію?**

Дію виконує **модуль прийняття рішень** (decision module) у складі програмної системи. Він отримує ймовірність від класифікатора і на основі порогу вирішує, яку мітку присвоїти.

**У який момент доступні ознаки?**

Ознаки (100 числових значень `X1..X100`) доступні **після сканування ділянки рельєфу** (наприклад, після обробки даних лідара або висотоміра). Тобто на момент прийняття рішення всі 100 точок уже відомі.

**Через який час можна отримати правильну мітку?**

Правильна мітка може бути отримана **після експертної перевірки** або **після обробки даних вищої точності** (наприклад, ручна розмітка геодезистом). Затримка може становити від кількох годин до кількох днів.

### 2.2. Наслідки помилок

**False Positive (FP):** Система прогнозує `ŷ = 1` (пагорб), але насправді це долина (`y = 0`).
- **Наслідок:** Ділянка помилково позначається як височина. Це може призвести до **непотрібного ускладнення маршруту** (обхід «пагорба», якого немає) або до **хибного спрацювання** в системі попередження. Втрати: час, ресурси, можливе зниження довіри до системи.

**False Negative (FN):** Система прогнозує `ŷ = 0` (долина), але насправді це пагорб (`y = 1`).
- **Наслідок:** Ділянка помилково позначається як низовина. Це може призвести до **прокладання маршруту через небезпечну височину**, що загрожує **безпеці** (наприклад, дрон може зіткнутися з рельєфом). У критичних системах FN є **більш небезпечним**, ніж FP.

## 3. Опис даних

**Джерело:** [UCI Machine Learning Repository — Hill-Valley](https://archive.ics.uci.edu/dataset/166/hill+valley) (ID 166).

**Розмір:** 606 екземплярів, 100 числових ознак (`X1`–`X100`), 1 бінарна цільова змінна (`class`: 0 = valley, 1 = hill).

**Типи ознак:** Усі ознаки — дійсні числа (координати точок на графіку).

**Цільова змінна:** `class` — бінарна, незбалансована (приблизно 50/50).

**Проблеми якості даних:** Пропусків немає. Дані синтетичні, без шуму (у версії `Hill_Valley_without_noise`). Можлива наявність шумової версії для окремих експериментів.

---

## 4. План експерименту

**Модель:** `LogisticRegression` з `C=1.0`, `solver='lbfgs'`, `max_iter=1000`.

**Preprocessing:** `StandardScaler` у складі `Pipeline`.

**Train/test split:** 80/20, `random_state=42`, стратифікований за `y`.

**Крос-валідація:** `StratifiedKFold` з 5 фолдами, `shuffle=True`, `random_state=42`.

**Спосіб отримання балу:** `predict_proba` (ймовірність класу 1).

**Метрики для OOF:** ROC-AUC та accuracy (проміжна оцінка).

**Що не входить на цьому етапі:** сітка порогів, калібрування, вибір політики, одноразовий test.

## Примітки

- `score` у OOF-таблиці — це **ймовірність**, оскільки використано `predict_proba`. Якщо б використовувався `decision_function`, значення не можна називати ймовірністю без калібрування.
- Наступні кроки: сітка порогів → аналіз наслідків FP/FN → калібрування → політика → одноразовий test.
