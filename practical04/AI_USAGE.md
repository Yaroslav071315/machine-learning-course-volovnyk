# Використання генеративного ШІ

## Огляд

Під час виконання цієї практичної роботи генеративний ШІ використовувався для таких цілей:

1. **Генерація шаблону коду** для завантаження даних Hill-Valley через `ucimlrepo`, створення Pipeline та отримання OOF-балів.
2. **Структурування README.md** відповідно до вимог інструкцій (розділи 1–8).
3. **Формулювання контексту рішення** (опис класів, дій, наслідків FP/FN).

## Конкретні випадки

### 1. Код для OOF
- **Запит:** «Створити код для отримання OOF-балів з використанням StratifiedKFold та cross_val_predict для Pipeline».
- **Отримано:** шаблон коду, який було адаптовано під конкретний набір даних (Hill-Valley) та модель (LogisticRegression).
- **Перевірка:** код виконано, перевірено розмірність OOF-масиву, відповідність `object_id`, розподіл за фолдами.

### 2. README.md
- **Запит:** «Створити README.md для практичної роботи з бінарної класифікації згідно з наданою структурою звіту».
- **Отримано:** текстовий каркас, який було наповнено конкретними даними про Hill-Valley та обрану модель.
- **Перевірка:** перевірено відповідність розділам 1–8 інструкцій, наявність опису FP/FN, фіксації протоколу.

### 3. Контекст рішення
- **Запит:** «Запропонувати прикладний контекст для класифікації hill/valley з діями системи та наслідками FP/FN».
- **Отримано:** приклад із модулем аналізу рельєфу для дрона/ГІС.
- **Перевірка:** контекст адаптовано під реальні сценарії використання, наслідки FP та FN розписано окремо.

## Що не використовувалось

- ШІ не використовувався для прийняття рішень щодо вибору моделі або гіперпараметрів — ці рішення зафіксовані відповідно до лабораторної роботи №2.
- ШІ не генерував остаточні висновки або аналіз результатів — ці розділи заповнюються після виконання експериментів.

## Висновок

Використання ШІ обмежувалося допоміжними задачами: генерація шаблонного коду, структурування тексту, формулювання прикладних прикладів. Усі ключові рішення (вибір моделі, протокол експерименту) приймалися самостійно та зафіксовані в README.
